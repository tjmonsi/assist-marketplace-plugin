## Ordering Rationale

- **Steps 1 to 10 (Tranche 1):** The fail-closed option (Step 1) comes first because the PR guard and later guards use it; D-1 is settled, so no Tranche 1 step waits on it. The confirmation store (Steps 2, 3) precedes the guard that reads it (Step 4). Staging (Step 5) precedes the secret scan (Step 6) because the scan reads staged changes. The push-grant check (Step 7) and the revision-loop cap (Step 8) are independent. Tests (Step 9) follow the code. Step 10 marks only gaps 3 and 6 closed, because each depends only on earlier Tranche 1 steps (Steps 5 to 8). It does not mark gap 2.
- **Steps 11 to 20 (Tranche 2):** The chain library (Step 11) precedes the writer (Steps 12, 13), the verifier (Step 14), and every feature that logs. The shell write path (Step 15) follows the protected paths it guards, and it marks gap 2 closed because that closure depends on Steps 2, 3, 4, and 9 plus the shell closure itself. Step 15 reads the protected list rather than naming the later governance configuration paths, so it covers `.claude/settings.json` and `.agent/governance/profile.json` once Step 23 adds them, the session purpose record once Step 24 adds it, and the rule-mode store once Step 32 adds it. Approval status (Step 16) needs the deny record from Steps 12 and 15. Gate evidence (Steps 17, 18) writes into the log. The advisory guardrail (Step 19) logs deny and pass records and so needs Step 12. Tests are Step 20.
- **Steps 21 to 30 (Tranche 3, 12 steps: ten numbered plus 27a and 27b):** Identity (Step 21) and the event schema (Step 22) come before the profile configuration (Step 23). Step 23 holds the direct committed-source flag read, the `profile.json` loader, the opt-out logging, and the protection of both configuration files (D-12); every later step that reads a profile flag depends on it. The purpose-capture hook (Step 24) writes the session purpose record, and the FERPA internal access log and the HIPAA audit log (Steps 25, 26) read it, so Step 24 precedes both. The PHI outbound guard (Step 27) is followed by the FERPA disclosure guard (Step 27a) because 27a reuses Step 27's outbound payload extraction and sits in the same NFR-028 fail-closed set; its tests (Step 27b) follow it directly. The two suffixed ids keep every existing step number stable. The BAA step (Step 28) follows.
