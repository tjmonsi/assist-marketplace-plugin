## Key Design Decisions

1. **WET, Not DRY** — Writing standard blocks are embedded in each skill/agent file (not cross-referenced) because skills cannot reliably perform runtime file lookups. This is intentional to ensure portability.

2. **No Cross-File Links** — Pasted blocks contain no `[[link]]` syntax or `see DOCUMENTATION_STANDARD.md` references. Each block is self-contained.

3. **Auto-invocation** — `review-md` runs automatically after every report-producing skill finishes, plus manually via `/review-md <file>`. This enforces the standard actively.

4. **Three-Part Finding Structure** — All report templates restructured to: What Happened, Why It Matters, What To Do Next. This reduces narrative prose and token cost.

5. **Traceability Format** — `[REQ-123|SPEC-45]` combined syntax. IDs sourced from requirements/spec docs or task prompts only — never invented.

## Token Cost Impact

- Foundation docs: ~135 lines of human-readable standard (one-time read, ~800 tokens)
- Pasted blocks: ~11-15 lines per agent/skill file (loaded once per invocation)
- review-md output: Only created when issues found; "No issues found" is single-line output (minimal cost)
- Overall: Writing standard reduces output token cost by cutting hedges, repetition, and narrative filler. Auto-check catches drafts before they reach the user.
